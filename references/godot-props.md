# Godot 정적 기물 — 형상·베이크·번들·메모리 최소화

Claude Code와 Codex의 `model` 스킬이 함께 사용하는 **정적 맵 기물 제작 절차**다.
나무·풀·바위·벽·펜스·건물처럼 리그 없이 배치하는 기물에 적용한다. `--kind prop`이라는
플래그만으로 용도를 판단하지 않는다. 액터의 장착 무기·장비는 [액터 파이프라인](godot-pipeline.md)을 따른다.

정책은 [SSOT §3.1](../../game/references/SSOT.md#prop-resource-budget), 제작 근거는
[GAME-DESIGN.md §5](../../../../GAME-DESIGN.md#prop-resource-budget)가 정본이다.
**기물의 번들 사이즈와 CPU·GPU 메모리를 절대적으로 최소화한다.** 원본 해상도·미세 무늬를
유지하려고 런타임 비용을 키우지 않는다. 필요한 식별성·실루엣·충돌·저사양 60fps 목표는 유지한다.

## 1. 입력·목표·출력부터 확인한다

1. 현재 씬·원본·재생성 도구를 읽는다. 기존 결과가 있으면 재사용하고 사용자의 변경을 보존한다.
   새 생성이 필요하면 [Tripo 조작 절차](tripo-studio.md)를 따른다. `Topology=Triangle`,
   `Ultra Mesh Quality=OFF`를 출발점으로 기물별 목표 `Polycount`를 정한다. 정적 기물은
   T-Pose·스켈레톤을 요구하지 않는다. 생성 원본의 텍스처 품질과 최종 런타임 해상도는 별도로 정한다.
2. 원본의 삼각형, 정점, 재질, 텍스처 해상도·채널, 투명도, 연결된 부품과 실제 크기를 조사한다.
   GLB 내보내기는 UV 경계·법선·색상 경계에서 정점을 나눌 수 있으므로 Blender 정점 수만 보지 않는다.
3. 기물별로 번들·CPU/GPU·삼각형·재질 목표를 잡는다. 액터 1,600삼각형을 기물 기본값으로 복사하지 않는다.
   **가능하면 그보다 훨씬 적게** 만들며 단순 기물은 더 줄인다. 약 100KB는 아래 사례의 목표이지
   모든 기물의 공통 상한이 아니다. 기존 건물 메시 5KB 이하 등 SSOT의 별도 예산도 지킨다.
4. 기본 게임 카메라와 최대 확대(`size = 1.5m`, 직교 pitch −45°)에서 남겨야 할 실루엣·색 구획·구멍을 정한다.
   크기는 기물의 용도에 맞춘다. 액터의 키 1.8m를 모든 기물에 적용하지 않는다.
5. 원본 FBX/GLB·연결 이미지·라이선스/출처·제작 `.blend`·고해상도 베이크는
   `game-assets/props/<분류>/<이름>/`의 `.gdignore` 적용 범위 안에 보존한다. 입력 파일은 덮어쓰지 않는다.
   최종 결과는 **사용자가 지정한 `maps/props/.../<이름>/` 폴더 안에 `.tscn`·GLB·재질·텍스처를 함께** 둔다.
   자연어로 지정한 경로도 유효하다. 지정이 없으면 스킬의 `outputs/` 기본 규칙을 따른다.
   런타임 폴더에 원본·백업·로그·측정 JSON을 넣지 않는다.

## 2. 형상을 먼저 이해하고 적은 면으로 재구성한다

**정적 기물은 감축·리토폴로지·베이크 카드화를 수행한다.** 액터용 “받은 삼각형을 그대로 유지” 규칙을
적용하거나, 이미 승인된 기물 최적화를 위해 사용자의 숫자 지시를 다시 요구하지 않는다.

| 형상 | 우선 적용할 방법 | 검수할 부분 |
|---|---|---|
| 줄기·바위·벽 등 연속된 덩어리 | 부품별 Decimate 또는 실루엣 중심 리토폴로지 | 바닥·끝점·두께·주요 굴곡, 작은 부품의 예산 독식 |
| 펜스 격자·기둥·반복 구조 | 원본 위치·단면·간격을 측정해 낮은 면 수로 재구성 | 구멍·교차부·기둥 윤곽, 반대편에서 보이는 실제 두께 |
| 반복 잎·가는 표면 | 원본 잎 색·알파를 카드에 베이크하고 대표 패턴 재사용 | 카드 위치·각도·크기·나무 전체 실루엣, 알파 경계 |

전역 Decimate로 구멍이 찢어지거나 목표 아래로 줄지 않으면 같은 감축을 반복하지 않는다.
형태별로 분리해 리토폴로지·카드·패턴 재사용을 비교한다. 펜스에서는 원본 격자와 기둥 단면을 측정해
재구성했다. 실제 구조를 단순화하는 이 작업을 캐릭터를 구슬·막대기로 대체하는 금지 사례와 혼동하지 않는다.

남아 있는 중복 정점은 필요한 UV·색 경계를 유지하면서 합친다. **최종 GLB의 삼각형·정점·속성과
임포트 후 LOD 버퍼**를 다시 확인한다. 삼각형만 적고 정점 데이터가 큰 결과를 완료로 보지 않는다.

## 3. 미리 베이크하고 패턴·팔레트를 재사용한다

여기서 **bake**는 원본 표면의 색·알파, 또는 필요한 고정 명암을 제작 단계에서 최종 albedo 등에
기록하는 것이다. 2.5D 애니메이션 스프라이트 시트, 본 감축을 위한 애니메이션 베이크,
Godot `LightmapGI`와는 다른 작업이다. **베이크만으로 파일·메모리가 작아지지는 않는다.**
같은 2K 출력에 더 많은 샘플을 계산하는 것은 제작 시간을 늘리지만, 더 큰 출력 해상도·맵·정점은 런타임 비용을 늘린다.

| 표면 | 경량화 방법 |
|---|---|
| 잎·껍질·벽의 반복 무늬 | 모든 조각을 고유 이미지로 굽지 않는다. 대표 패턴을 고르고 UV를 재사용해 작은 아틀라스에 배치한다. 패턴 선택·군집화는 재생성 가능한 고정 시드/결정적 방식으로 수행한다 |
| 작은 단색 구획·금속 막대 | 원본 albedo에서 면별 색을 샘플링해 작은 팔레트로 묶는다. 펜스는 64색을 8×8 이미지에 넣고 각 면의 UV를 해당 픽셀 중심에 모았다 |
| 근거리에서 반드시 보여야 하는 고유 무늬 | 필요한 영역만 배정한다. 먼저 UV 재배치·패턴 공유를 개선하고, 그래도 식별성이 부족한 경우에만 해상도를 높인다 |

**런타임 텍스처는 필요한 최소 해상도**로 만든다. 액터의 1024 기본값이나 Tripo 제작 원본의 2K를
기물의 최소값으로 쓰지 않는다. 2K는 필요한 경우의 **공유 아틀라스 선택지**다.
단순히 PNG를 더 잘 압축해도 디코딩된 텍스처 메모리가 같은 경우가 있으므로 임포트 형식까지 확인한다.

- 기본 **재질 슬롯 1개·공유 `StandardMaterial3D`·`UNSHADED`**, 런타임 광원 0개를 유지한다.
  normal/roughness/metallic 맵에만 있던 필요한 외관은 먼저 albedo에 반영하고, 사용하지 않는 맵·슬롯을 제거한다.
  런타임 `LightmapGI`·실시간 그림자로 원본을 재현하지 않는다.
- 불투명 구조는 opaque·뒷면 컬링을 기본으로 한다. 잎 카드에 필요한 경우만 `alpha_scissor`와 양면을 쓴다.
  나무의 scissor 0.5는 사례값이다. 작은 아틀라스의 알파 경계·패딩·밉맵을 확인하며 넓은 반투명 면 중첩을 피한다.
- 정점 색을 쓰는 후보는 데스크톱 Forward Mobile과 Android Compatibility의 색을 모두 확인한다.
  펜스의 정점 색 후보는 A12에서 어두워져 **소형 albedo 팔레트**로 교체했다. 데스크톱만 보고
  색 공간 처리가 같다고 가정하거나 근거 없는 밝기 배율·고유 셰이더를 추가하지 않는다.
- 같은 종류의 인스턴스는 메시·재질·텍스처를 공유한다. 종류 간에도 기존 패턴·재질 재사용을 먼저 검토한다.
  반복 배치는 `MultiMesh`를 고려하되, 복제 메시 병합으로 정점 메모리를 늘리지 않는다.
- 🛑 흔들림·나부낌·흐름 같은 **움직임은 구운 프레임 메시 교체**로 만든다(Royal 모바일 분수 방식 · SSOT §2 · 2026-09-09 사람 결정).
  기물 전용 `vertex()` 셰이더를 만들지 않는다 — A12 에서 첫 표시 컴파일이 2,952ms 였다. 씬은 프레임 0 정지 메시만 들고
  프레임 묶음은 입장 뒤 로드한다. 움직이는 정점만 굽고 장수는 끊기지 않는 최소로. 절차는 design.md 결정 20.

## 4. GLB·임포트·배치 씬 설정

자세·축·바닥 원점은 Blender/GLB에서 고친다. Godot 기준 **+Y up·바닥 Y=0**, 방향은 실제 배치 용도에 맞추고
잘못된 자세를 부모 회전으로 상쇄하지 않는다. 최종 모델 루트의 회전·스케일은 항등, `.import`의 `root_scale=1.0`이다.
정적 기물 크기 조절만 [SSOT §3.2](../../game/references/SSOT.md)의 예외대로
기물 루트 바로 아래 **`Body.scale` 한 곳에서 균등하게** 한다. 루트·청크 인스턴스 스케일은 `(1,1,1)`,
메시와 충돌은 모두 `Body` 아래에 둔다. 충돌은 용도에 맞는 단순 형상을 쓴다. 펜스의 작은 시각적 구멍은
이동 가능한 구멍이 아니므로 해당 사례에서는 벽 전체 BoxShape3D 하나를 사용했다.

| 설정/데이터 | 기물 기준 |
|---|---|
| GLB | 필요한 `POSITION`·UV·인덱스 등만 유지. 필요 없는 탄젠트·UV2·색·리그·애니 제거. 법선도 재질과 렌더링에 불필요함을 검증한 경우에만 제거 |
| `nodes/root_scale` | `1.0` |
| `meshes/ensure_tangents` | `false` — 제거한 탄젠트를 임포터가 다시 만들지 않도록 |
| `meshes/create_shadow_meshes` | `false` |
| `meshes/light_baking` | `0` — UV2/LightmapGI용 데이터 생성 안 함 |
| `animation/import` | `false` — 정적 기물에 본·RESET·애니메이션 폴더 요구 안 함 |
| `meshes/generate_lods` | 기본 `true`. 생성된 버퍼 비용을 포함해 측정하며 단순 형상은 효과와 비용을 비교 |
| 재질 연결 | 외부 공유 `.tres`를 임포트 재질에 연결. 불필요한 중복 내장/외부 텍스처가 export에 같이 들어가지 않는지 확인 |
| 잎 등 일반 패턴 텍스처 | 모바일 지원 압축 형식·알파 품질·밉맵을 검증. 나무는 128² RGBA·밉맵·Android ETC2 RGBA8 사용 |
| 면마다 UV가 상수인 초소형 팔레트 | 펜스는 8²·`compress/mode=0`(lossless), `detect_3d/compress_to=0`, 밉맵 OFF, nearest·repeat OFF. **이 예외를 일반 표면 텍스처에 복사하지 않는다** |

`.import`·`.tres`·`.tscn`은 현재 프로젝트 규칙대로 직접 수정·재임포트·검증한다.
옛 “사람만 설정” 문구 때문에 작업을 넘기지 않는다. `maps/`에는 게임 로직 `.gd`를 두지 않고
기존 [MapProp](../../../../scripts/map_prop.gd)과 씬 구조를 재사용한다.

기존 스크립트의 인자는 현재 구현을 확인해 쓴다. 정규화 원본을 보존하는 첫 단계 예시:

```bash
blender --background --factory-startup --python-exit-code 1 \
  --python .claude/skills/model/scripts/normalize_for_godot.py -- \
  <입력.glb> game-assets/props/<분류>/<이름>/<이름>_source.blend \
  --kind prop --forward skip --triangles 0
```

`--triangles 0`은 **초기 정규화에서 원본 형상을 보존**하려는 값이지 최종 기물 감축 금지가 아니다.
현재 normalizer는 인자를 생략하면 `4800`을 사용하므로 값을 명시한다. `--kind prop`의 `--height`는
명시한 경우에만 크기를 맞춘다. `--forward skip` 뒤 실제 축은 별도로 검수·교정한다.
이후 형상별 도구로 줄이고 [export_godot_glb.py](../scripts/export_godot_glb.py)에
`--kind prop`과 검증한 텍스처 최대 변을 명시한다. 내보내기만으로 불필요한 속성이 모두 제거된다고 가정하지 않는다.
Blender 배치 실행은 **`--python-exit-code 1`**을 붙여 Python 예외가 성공 종료로 보이지 않게 한다.

## 5. 완료 검증과 용량 보고

제작 작업은 Godot 임포트 후 `./doctor.sh art --scene <기물씬>`부터 관련 검사를 수행한다.
GLB 검사에는 [verify_godot_glb.py](../scripts/verify_godot_glb.py)의
`--kind prop --tris <해당목표> --tex <해당최대변>`을 명시한다. 액터용 키·본·애니 검사를 기물에 강제하지 않는다.
씬을 실제 로드해 크기·바닥·재질·충돌·리소스 공유를 확인하고, 여러 방향과 최대 확대 스크린샷을 직접 열어 본다.
Godot 실행 → 필요한 export 검증 → Galaxy A12 등 저사양 Android 실기기 검증을 수행한다.
관련 명령은 [GAME-COMMANDS.md](../../../../GAME-COMMANDS.md)와 아래 사례의 재생성 기록을 따른다.

| 측정 항목 | 반드시 구분할 범위 |
|---|---|
| 원본 파일 | PNG·GLB 바이트와 원본 삼각형/정점은 전후 비교용. RAM·최종 번들 크기를 대신하지 않음 |
| export 패키지 | 대상 APK/PCK의 실제 메시·CTEX·재질·씬·remap 엔트리 저장 크기. 포함 항목·압축 여부를 기록하고 공유 텍스처를 중복 또는 누락 집계하지 않음 |
| 공유 GPU 비용 | 임포트된 메시·LOD 버퍼와 텍스처의 압축 형식·밉맵 포함 엔진 집계 |
| CPU 비용 | 공통 셰이더·물리 등을 예열한 기준 상태에서, 해당 리소스와 한 인스턴스 로드 후 안정된 할당 증가 |
| 추가 배치 비용 | 같은 리소스의 1개/여러 개를 비교해 GPU 공유 여부와 노드·콜리전 등 추가 CPU 할당을 따로 계산 |
| 앱 전체 | 엔진·드라이버·Java·최초 셰이더 준비 등 공통 비용 및 OS 프로세스 메모리는 별도. 에셋 할당 합계를 PSS/RSS 증가량이라고 부르지 않음 |

리소스 캐시 때문에 다시 로드하지 않고 0바이트라고 측정하지 않는다. 예열·해제·재로드와 기준 씬을
고정하고 코드·로그·장치·엔진 버전·렌더러·debug/release 조건을 남긴다.
사례의 CPU 정적 메모리 모니터는 debug에서 측정했고 GPU는 release에서도 대조했다.
**해당 release에서 지원되지 않는 CPU 모니터의 0을 실제 메모리 0으로 보고하지 않는다.**
측정하지 못한 값은 추정/미측정으로 구분하며, 장치가 없으면 “모바일 미확인”, iOS를 실행하지 않았으면 “iOS 미검증”을 적는다.
에셋 1종 검증을 다수 액터·기물·이펙트가 보이는 게임 전체 60fps·발열 검증으로 확대하지 않는다.

문서만 수정하는 작업에서는 경로·내용·diff를 검증하고 앱을 빌드하지 않는다.
